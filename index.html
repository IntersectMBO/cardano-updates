Mithril Team Update

October 21, 2026 · 3 min read
Jean-Philippe Raynaud
Mithril Tech Lead

High level overview​

This week, the Mithril team released the 2642 distribution. This version reads the protocol configuration from the Cardano chain in the signer and the aggregator, supports the Cardano node 11.1.3 and the DMQ node 0.7.2.0, and removes the support for the Gzip compressed snapshot archives. It also introduces a certificate chain cache in the client, support for compact SNARK certificates with a genesis-signed registry of the trusted circuit verification keys, and preliminary support for IPFS as a storage location of the immutable files (all unstable). It includes various bug fixes and improvements as well.

The team also published the immutable archives directory of the aggregator under an IPNS name, and selected a crate for the user interaction of the setup command. They kept working on the deterministic resolution of the SNARK verification key collisions in the key registration, the progressive rollout strategy of the IPFS distribution, the new mithril-setup crate, and the findings of the M1.1 milestone audit.

Finally, they worked on the upgrade to Cardano node 11.2, the renaming of DeprecatedCommand to RemovedCommand in the client CLI, the cleanup of the mithril-test-lab directory, and the investigation of the blocks and transactions verification failure on the testing-preview network.

Plutus Core Team Update

October 21, 2026 · 2 min read
Ziyang Liu
Software Engineering Lead

High level summary​

The Plutus team has enabled multiIndexArray (CIP-0156) and the new Value builtins policies, assetCount, keepPolicies and dropPolicies (CIP-0168) at Dijkstra for all Plutus ledger language versions. These require the Dijkstra hard fork before they can be used on-chain. We've also added conformance tests for multiIndexArray, brought the specification's versioning section up-to-date, and added casing on Data to the Agda metatheory.

The guardrail script now supports optional parameters that governance proposals can set or unset, and the Plinth compiler can report timings for individual compilation stages. Work in progress includes generating Agda typechecking tests from conformance tests, and CEK machine optimizations.

Key Pull Requests Merged​

  • Enable new builtins at Dijkstra
  • Publish plutus-executables to CHaP
  • Ship prebuilt executables for macOS, built by Hydra
  • Guardrail: support optional parameters
  • Add plugin option to dump compilation timing
  • Respect target version when compiling Data casing
  • Apply script deserialisation bounds unconditionally
  • Update protocol and ledger language versioning in the specification
  • Add casing on data to the metatheory
  • Add multiIndexArray conformance tests

Pull Requests In Progress​

  • Add tool to generate Agda typechecking tests from conformance tests
  • Add bytestring to metatheory
  • Replace Vector with Array in the evaluator

Ledger Team Update

October 14, 2026 · 4 min read
Alexey Kuleshevich
Ledger Team Software Engineer

High level summary​

Leios continued to be the main focus this cycle and moved well beyond prototype on several fronts. Dijkstra forecasting for Leios landed, the forecasting itself was simplified by keeping stake data only in snapshots, and DijkstraEraForecast was extended with the Peras protocol parameters. We defined Leios' EndorserBlock, added a ledger state query for the Leios committee, switched the Leios header KES signature verification to use MemoBytes, and fixed pool BLS key handling so the key's epoch number is only renewed when the key is actually new. These were backed by tests for the Leios committee and stake distribution when injecting genesis data, and by integration of the latest Leios changes for week 41.

PlutusV4 reached a milestone for the Dijkstra era: eraMaxLanguage is now set to PlutusV4, and AlonzoTxWits encodes and decodes PlutusV4 scripts starting with Dijkstra. Work on sub-transactions continued, with allInputsTxBodyF now looking into sub-transactions, top-level supplemental datums allowed for sub-transactions, and tests added for refunds in the consumed value across a batch. On the Dijkstra era more broadly, we fixed VRF reuse at the epoch boundary, started tracking the VRF key hashes of genesis stake pools, moved NonMyopicMemberRewards into the ledger, added missing getters to AnyEraTxBody, and renamed requiredTopLevelGuardsL while bringing in its outstanding tests.

On testing and releasing we added further Entities tests, treasury value and reference-script size tests, enabled bootstrap addresses in conformance, updated the formal ledger specification, and bumped the Plinth version in the Plutus preprocessor modules. Infrastructure changes included a cardano-data changelog fix for the pointWise to pointwise rename, a round of package version bumps across the changelogs following a CHaP release, and the usual dependency bump.

Mithril Team Update

October 7, 2026 · 3 min read
Jean-Philippe Raynaud
Mithril Tech Lead

High level overview​

This week, the Mithril team completed adding a Proof of Bound Possession for the SNARK verification keys, renaming the future_snark feature to snark, adding the missing conversion and error-path tests in IVC SNARK, and testing the SNARK infrastructure to full security parameters with the Midnight fix. They kept working on hardening the SNARK primitives.

The team completed adding an IndexedDB backend for the certificate chain cache in the WASM client and documenting the certificate chain cache, fixed the IPFS end to end tests failing when dist.ipfs.tech is unreachable, and fixed the crates publication dry run failing in the nightly. They also worked on the new distribution release, the upgrades to Cardano node 11.1.3 and 11.2, the update of the DMQ node to 0.7.2.0, a keypair generation tool in the aggregator CLI, and kept investigating the blocks and transactions verification failure on the testing-preview network.

Finally, they completed the upgrade to Rust 1.99, and fixed the missing SPO aliases in the explorer, the flakiness of the end to end tests caused by the devnet scripts, and the cloud uploader cache which only held the first 1000 files.
